# Predictive-value study: does NIFTY's forward return have any predictable direction at all?

Generated by `research/ml/direction_predictability_study.py`. Full output:
`direction_predictability_NIFTY.json`.

## Context: why this study, separate from `chain_replay.py`

`chain_replay.py`'s Phase 1 replay found `analysis.technical`'s trend-driven
direction call correct only 32.9% of trades — worse than a coin flip — on
real recorded NIFTY option chains, with the loss concentrated entirely in
that wrong call (see `chain_replay_NIFTY_findings.md`, "Root cause 2a").
That result was measured through the full signal-engine pipeline (chain
gates, spread pricing, exit rules) on 85 trades, which raises an honest
question: is it the *classifier logic* that's failing to capture a real
signal, or is there no signal to capture at this horizon at all?

This study answers that directly and separately, stripped down to the
smallest form the question can take: no options, no spread pricing, no
exit rules, no signal-engine gates — just NIFTY's own forward return,
predicted from ~15 standard technical features (RSI, MACD, ADX, Bollinger
bands, ATR, realized volatility, etc., via the same leakage-safe
`research.features.FeatureEngine` the shipped ML scaffolding is built
around), with two standard classifiers (logistic regression, random
forest) and proper **purged walk-forward validation** — never a single
train/test split, which is exactly the setup that produces the misleadingly
high in-sample accuracy the academic literature on this topic warns about
(see the prior web research: 80–87% in-sample accuracy on similar technical
features collapsed to 47–49% out-of-sample in peer-reviewed work).

## Verdict: **NO_PREDICTIVE_VALUE_FOUND — independent confirmation of the chain_replay result**

| | |
|---|---|
| Horizon | 125 bars (~5 trading days at 15-min candles — the midpoint of chain_replay's 3–7 DTE window) |
| Labels | UP / DOWN / FLAT, ±0.5% forward-return threshold |
| Folds evaluated | 8 (purged + embargoed, expanding window) |
| **Folds clearing 55% accuracy** | **0 of 8** |
| Folds beating their own fold's majority-class baseline | 3 of 8 |
| Best single fold accuracy | 45.1% (fold 4, RandomForest) — still below the 55% gate |
| Worst single fold accuracy | 21.3% (fold 3, LogisticRegression) |

Zero of eight folds cleared the bar, and several folds performed **worse
than trivially guessing the more common class** — fold 7's majority
baseline was 61.4% (a lopsided period, correctly flagged rather than
hidden by reporting only one aggregate number) while both models scored
25–32% there, meaningfully *below* free information already available
from the label distribution alone.

This is a second, independent line of evidence, using a different method
(supervised ML with engineered features and formal walk-forward
validation) on the same underlying question the trade-level replay
answered empirically. Both point the same way.

## What this does and does not rule out

- **Rules out:** short-horizon (~5 trading day) NIFTY direction being
  predictable from *these* ~15 standard technical/price-action features
  computed from spot price alone. This is a fairly comprehensive standard
  feature set (momentum, trend strength, volatility, mean-reversion bands),
  so a negative result here is informative, not just "we tried one thing."
- **Does not rule out:** a different horizon (shorter, e.g. intraday; or
  longer, e.g. 10–20 days), options-flow features (PCR, OI change, IV
  skew — unavailable for this study since the legacy dataset that has deep
  spot history has no matching options-flow history recorded at the same
  density; SENSEX's new recorder captures this, once enough history
  accumulates), or a fundamentally different approach (regime-conditional
  models, cross-asset features, news/sentiment). None of those were tested
  here and none should be assumed to fail just because this did.
- **Does not test option economics** — that's deliberately
  `chain_replay.py`'s job, not this module's (see
  `research/ml/targets.py`'s own docstring on why a correct directional
  call and a profitable option trade are different questions). A
  hypothetically fixed direction signal would still need to pass through
  the moneyness gate, cost model, and exit rules chain_replay already
  exercises.

## Recommendation

1. **Stop trying to fix `analysis.technical`'s trend classifier for this
   specific purpose.** Two independent methods now agree there is no
   exploitable signal in standard technical features at a ~5-trading-day
   NIFTY horizon. Further tuning of thresholds, weights, or the specific
   trend-labeling logic in that module is very unlikely to change this
   verdict, because the problem is upstream of any particular
   implementation choice.
2. **The strategic question is now genuinely open**, not a bug to fix:
   either (a) find a different, testable source of edge — options-flow
   features once SENSEX data accumulates, a different horizon, or a
   fundamentally different approach — or (b) accept that a pure
   directional-bet structure (long calls/puts, debit verticals) may not
   have a rule-based edge at this account's timeframe, and consider
   whether a non-directional or volatility-based strategy family is worth
   evaluating instead. This is a decision for the user, not something to
   resolve by writing more code against the same feature set.
3. **If a new data source or horizon is tested**, reuse this module's
   purged walk-forward machinery (`_rolling_folds`, `purge_and_embargo`)
   rather than a single train/test split, for the same reason this study
   was built this way in the first place.
